# ADR-0007: 全タスクで Implementer → Verifier → Debugger の3エージェント方式を適用

- Status: accepted (updated)
- Date: 2025-03-23 (originally 2025-03-18)

## Context

Sisyphus の実装フェーズで、1つのエージェントが実装・テスト・修正を全て行っていた。同じエージェントが書いたコードを自分で検証すると、確認バイアスにより問題を見落としやすい。実際の開発チームでも「自分のバグは自分で見つけにくい」のは既知の問題。

当初は M-L タスクのみ3エージェント方式、S タスクは自分でテストとしていたが、S タスクでも確認バイアスは発生する。「自分でテストして通った」は信頼できない。

## Decision

全タスクで3エージェント方式を適用する。タスク規模による分岐は廃止。

- **Implementer（自分）**: コードを書く。テストは実行しない
- **Verifier**: adversarial に検証。壊せるか試す。書いた人の「動くはず」を信用しない
- **Debugger**: Verifier が fail を報告した場合のみ spawn。先入観なしで根本原因を調査

重要な原則: Debugger の修正結果は Implementer ではなく **Verifier に戻す**。修正者の「直した」を信用しない。

## Consequences

- **良い面**: 全タスクで確認バイアスを排除。品質が一貫する。「テスト通りました（実行せず）」が構造的に起きない
- **悪い面**: 全タスクでトークンコストが増加（Verifier spawn 分）。ただし品質問題の手戻りコストと比較すれば安い
