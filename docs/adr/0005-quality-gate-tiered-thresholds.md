# ADR-0005: Quality Gate を段階制にする（推奨 500行〜、強制 1500行〜）

- Status: accepted
- Date: 2025-03-17

## Context

stop-guard.sh は変更行数が閾値を超えた時に quality-gate を強制していた。当初は 500行で一律ハードブロックだったが、以下の問題があった。

- 500行程度の変更でも問答無用でブロックされ、作業の流れが止まる
- `/sisyphus` ワークフロー内では quality-gate が組み込まれているので二重チェックになる
- 一方で、完全に任意にすると quality-gate をスキップされるリスクがある

## Decision

段階制を採用する。

| 変更量 | 挙動 |
|--------|------|
| 500行未満 | 素通り |
| 500行〜1499行 | 推奨メッセージを表示（ブロックしない） |
| 1500行〜 | ハードブロック（従来通り） |

閾値は環境変数（`SISYPHUS_MIN_DIFF`, `SISYPHUS_FORCE_DIFF`）で変更可能。

## Consequences

- **良い面**: 普段の作業では柔軟に進められる。大規模変更では確実に品質ゲートを通す。ユーザーのストレスが減る
- **悪い面**: 500〜1499行の範囲では quality-gate がスキップされる可能性がある。推奨メッセージの効果は Claude の判断に依存する
