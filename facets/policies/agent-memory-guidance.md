# Agent Memory ガイダンス - 共通ポリシー

**エージェントが蓄積すべき知識と蓄積すべきでない情報**を定義する共通基準。

## 基本原則

### 蓄積すべきもの

1. **プロジェクト固有のパターン**: コードベースの慣習、命名規則、アーキテクチャの特徴
2. **繰り返し遭遇する事実**: 頻出するファイルパス、設定値、依存関係
3. **過去の判断とその根拠**: 技術選定の理由、設計上のトレードオフ
4. **失敗から学んだこと**: ハマりポイント、誤った前提、意外な制約
5. **ユーザーの好み**: コードスタイル、コミュニケーションスタイル、優先事項

### 蓄積すべきでないもの

1. **一時的な状態**: 現在のタスク進捗、セッション固有のコンテキスト
2. **推測・未検証の情報**: 1回の観察で一般化した結論
3. **すぐ陳腐化する情報**: バージョン番号、一時的な回避策
4. **他で管理される情報**: CLAUDE.md に記載済みの規約、コード内のコメント

## カテゴリ別ガイド

### 調査系（researcher, vision）

| 蓄積する | 蓄積しない |
|---------|-----------|
| プロジェクトのディレクトリ構造マップ | 個別のファイル内容 |
| 頻出パターンの場所と用途 | 一度きりの検索結果 |
| API の注意点・落とし穴 | 最新バージョン番号 |

### 分析系（analyst, scout）

| 蓄積する | 蓄積しない |
|---------|-----------|
| プロジェクト固有の制約・前提条件 | 個別タスクの要件 |
| よくある曖昧性パターン | セッション固有のスコープ判定 |
| 見落としやすいエッジケース | 一時的な仮定 |

### 設計・計画系（designer, planner, critic, advisor）

| 蓄積する | 蓄積しない |
|---------|-----------|
| アーキテクチャ決定の根拠 | 個別タスクの計画詳細 |
| 設計パターンの適用結果 | タスク ID やセッション内の進捗 |
| レビューで繰り返し指摘されるポイント | 一時的なレビューコメント |

### 実装・品質系（frontend, debugger, code-reviewer, security-reviewer）

| 蓄積する | 蓄積しない |
|---------|-----------|
| プロジェクト固有のコーディングパターン | 個別の diff 内容 |
| 頻出するバグパターンと根本原因 | セッション内の修正履歴 |
| プロジェクト固有の OK/NG 判定基準 | 汎用的な OWASP ルール |

## Worktree での auto-memory 共有

Claude Code 2.1.63+ では、**同一リポジトリの git worktree 間で project configs と auto-memory が自動的に共有される**。

`isolation: worktree` で動作するエージェント（frontend, designer, planner, debugger）が worktree 内で memory に書き込んだ内容は、メインの worktree にも反映される。エージェントは worktree かどうかを意識する必要はない。

## 更新タイミング

- **タスク完了時**: 新しいパターンや知見を発見したら蓄積
- **誤りを発見時**: 既存の memory が間違っていたら即修正・削除
- **繰り返し確認時**: 2回以上同じ情報を調べたら memory に追加

## 書き込みアクション（必須）

タスク完了前に以下を実行すること。`memory: project` により Write/Edit ツールは自動的に有効化されている。

1. **振り返り**: 今回のタスクでプロジェクト固有の知見（パターン、慣習、落とし穴）を発見したか？
2. **書き込み**: 知見があれば MEMORY.md に追記する（既存ファイルは Edit、新規は Write）
3. **スキップ**: 知見がなければ何もしない（空ファイルは作らない、無理に書かない）

> **重要**: この振り返りはタスクの最終ステップとして行う。結果を返す直前に1分だけ振り返る。

## MEMORY.md フォーマット

```markdown
# [エージェント名] Memory

## プロジェクト構造
- [プロジェクト固有の構造情報]

## パターンと慣習
- [繰り返し観察されたパターン]

## 注意点・落とし穴
- [ハマりポイント、意外な制約]

## ユーザーの好み
- [確認済みの好み・スタイル]
```

各セクションは必要に応じて追加・削除する。空のセクションは作らない。

## クロスリード（他エージェントの memory 参照）

タスク開始時に関連エージェントの MEMORY.md を Read して知見を活用する。

**原則:**
- **Read のみ**: 他エージェントの memory への書き込みは禁止
- **タスク開始時に1回**: `.claude/agent-memory/o-m-cc-{agent-name}/MEMORY.md` を Read
- **存在しない場合はスキップ**: memory ファイルがない = まだ蓄積がない。エラーにしない

### 参照マップ

| エージェント | 参照先 | 活用方法 |
|-------------|--------|---------|
| planner | debugger, code-reviewer | バグ傾向→テスト優先度、品質問題→タスク設計 |
| designer | code-reviewer, advisor | 頻出指摘→設計で回避、過去の意思決定→一貫性 |
| scout | critic | レビュー落とし穴→ギャップ分析精度向上 |
| code-reviewer | security-reviewer | セキュリティコンテキスト→品質判定に活用 |
| security-reviewer | code-reviewer | 品質コンテキスト→セキュリティ判定に活用 |

## Calibration Loop（自己校正）

reviewer 系（code-reviewer, security-reviewer, critic）が判定精度を振り返る。

- **過剰検知**: Warning を出したが実際は問題なかった傾向
- **見逃し**: 後で発覚した問題を検知できなかった傾向

MEMORY.md の `## Calibration` セクションに **傾向パターンのみ** 3-5行で保持。個別ケースは記録しない。

## プロジェクト成熟度マップ（researcher）

researcher が調査ごとにプロジェクト構造の知識を段階的に蓄積。

- **初回**: ディレクトリ構造スケルトン（主要ディレクトリと役割）
- **2回目以降**: 責務、ホットスポット、暗黙の依存関係を追記
- **粒度**: ディレクトリ/モジュールレベル（ファイルレベルまで降りない）
- **圧縮**: 古い情報は統合（個別エントリ→パターンに昇格）
