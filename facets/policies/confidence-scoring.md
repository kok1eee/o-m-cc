# Confidence Scoring - 共通ポリシー

**確信度の高い問題のみを報告し、ノイズを排除する**ための共通スコアリング基準。

## スコアリング基準（0-100）

| スコア | 確信度 | 報告 |
|--------|--------|------|
| 90-100 | 確実な問題 | **必ず報告** |
| 80-89 | 高い確信 | **報告** |
| 60-79 | 中程度 | 報告しない（ノイズ） |
| 0-59 | 低い確信 | 報告しない |

**重要: Confidence 80以上の問題のみを報告する。**

## スコアリング例

```markdown
## 90-100: 確実な問題
- SQLインジェクション脆弱性（パラメータ化されていないクエリ）
- ハードコードされたAPIキー/パスワード
- 明らかなNullPointerException
- 無限ループ

## 80-89: 高い確信
- shell=True のコマンド実行
- 適切でないエラーハンドリング
- 明らかなN+1問題
- 未使用のインポート/変数

## 60-79: 中程度（報告しない）
- 「もっと良い書き方があるかも」
- スタイルの好み
- 「通常はこうする」程度の提案

## 0-59: 低い確信（報告しない）
- コンテキスト不足で判断できない
- プロジェクト固有の規約かもしれない
```

## 出力分類

| レベル | Confidence | 表記 |
|--------|-----------|------|
| Critical | 90+ | `🔴 Critical（必須修正）- Confidence 90+` |
| Warning | 80-89 | `🟡 Warning（推奨修正）- Confidence 80-89` |
| Good | - | `🟢 Good（良い点）` |

## 結論テンプレート

```markdown
## 結論
- Critical: X件（Confidence 90+）
- Warning: X件（Confidence 80-89）
- 報告対象外: Y件（Confidence 80未満、ノイズとして除外）

→ Critical なし: マージ可能 / 承認
→ Critical あり: 修正が必要
```

## 共通原則

1. **Confidence 80以上のみ報告**: ノイズを減らし、重要な問題に集中
2. **具体的に**: 曖昧な指摘は避け、ファイル名と行番号を明記
3. **建設的に**: 問題だけでなく解決策も提示
