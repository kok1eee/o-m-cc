# /o-m-cc:handover - セッション引き継ぎ書

**セッションを振り返り、次の Claude がフルコンテキストでスタートできる引き継ぎ書を生成する。**

Stop hook の自動生成では書けない「なぜ」「教訓」をリッチに記録する。

---

## Step 1: 情報収集

以下を並列で収集する。

### 1a. 変更ファイル一覧

```bash
# jj が使える場合
jj diff --stat 2>/dev/null || git diff --stat HEAD 2>/dev/null || echo "変更なし"
```

### 1b. 計画ファイルの確認

**Glob** で `spec/plan/` 配下を確認：
- `spec/plan/requirements.md`
- `spec/plan/design.md`
- `spec/plan/tasks.md`
- `spec/plan/orchestration.yml`

存在するファイルを **Read** で内容を把握する。

### 1c. タスク状態

**TaskList** で現在のタスク一覧と状態を取得する。

---

## Step 2: 引き継ぎ書の生成

Step 1 で収集した情報と、**このセッション全体の会話コンテキスト**を振り返り、以下の構造で `spec/plan/HANDOVER.md` を生成する。

**Write** ツールで `spec/plan/HANDOVER.md` に書き出す：

```markdown
# Session Handover
> Generated: YYYY-MM-DD HH:MM

## 作業サマリー
- 何に取り組んだか
- 何が完了し、何が未完了か

## 意思決定ログ
| 決定 | 理由 | 代替案 |
|------|------|--------|
| ... | ... | ... |

## うまくいったこと / いかなかったこと
### うまくいったこと
- ...
### うまくいかなかったこと（バグ・問題とその修正）
- ...

## 教訓と注意点（Gotchas）
- 次の Claude が同じ轍を踏まないための注意点

## 重要ファイルマップ
| ファイル | 役割 | 状態 |
|----------|------|------|
| ... | ... | 完了/作業中/未着手 |

## ネクストステップ
1. 優先度の高い順に
2. ...

## 次のセッションへの申し送り
[フリーテキスト: 次の Claude が最初に知るべきこと。
コンテキストがない状態で読んでも理解できるよう、
背景・動機・制約を含めて書く。]
```

### 記述のガイドライン

- **具体的に書く** — 「バグを修正した」ではなく「認証トークンの有効期限チェックが off-by-one だった（auth.ts:42）」
- **意思決定の理由を残す** — 何を選んだかだけでなく、なぜそれを選び、何を捨てたか
- **教訓は再現可能に** — 「ハマった」ではなく「X をすると Y が起きるので Z する必要がある」
- **ファイルパスは正確に** — 存在確認済みのパスのみ記載

## Step 3: 完了報告

```
✅ 引き継ぎ書を生成しました

📄 spec/plan/HANDOVER.md
📊 作業サマリー: [1行の概要]
📋 ネクストステップ: [件数] 件

💡 次のセッション開始時に自動で案内されます。
```
