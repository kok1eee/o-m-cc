# Experiment - 実験駆動の反復改善ループ

**1回1変更。測定で判断。良ければ保持、悪ければ revert。**

sisyphus が計画駆動（要件→設計→実装）なのに対し、experiment は実験駆動（試す→測る→残す or 戻す）。

## いつ使うか

- パフォーマンス最適化（レスポンス時間、メモリ使用量）
- リファクタリング（品質改善、コード整理）
- UI/UX 改善（見た目、操作感の調整）
- バグ修正の試行錯誤（原因が不明で複数のアプローチを試したい）

## Step 1: ゴール設定

ゴールと測定方法を明確にする。

```
1. 何を改善するか（ゴール）
2. どう測定するか（ベンチマーク/テスト/スコア）
3. 現在のベースライン値を測定して記録
```

**ベースラインなしに改善は測れない。** 最初に必ず測定を実行する。

## Step 2: 改善ループ

以下を **ゴール達成まで** 繰り返す。

```
┌─────────────────────────────────────────────────┐
│  Iteration N                                     │
│                                                 │
│  1. 仮説: 「〇〇を変えれば△△が改善するはず」      │
│     — 1回の反復で 1つの焦点だけ変更する            │
│                                                 │
│  2. 変更を実装                                   │
│                                                 │
│  3. Verifier を spawn して検証                    │
│     Agent: subagent_type=general-purpose          │
│     prompt: "以下の変更を検証してください。         │
│     テスト/ベンチマークを実行し、                  │
│     ベースライン値との比較結果を報告。              │
│     改善/悪化/変化なしを数値で判定。"              │
│                                                 │
│  4. 判定                                         │
│     改善 → コミットして保持                       │
│       jj describe -m "experiment: [仮説と結果]"   │
│       jj new                                     │
│       ベースラインを更新                          │
│                                                 │
│     悪化/変化なし → revert                        │
│       jj abandon                                 │
│       仮説を記録（次の反復で避ける）               │
│                                                 │
│  5. 次の仮説を立てて 1 に戻る                     │
└─────────────────────────────────────────────────┘
```

### ルール

- **1反復1変更**: 複数の変更を同時にしない。何が効いたか分からなくなる
- **測定が全て**: 「良くなったはず」ではなく数値で判断
- **revert は失敗ではない**: 仮説が棄却されただけ。記録して次に活かす
- **Verifier に検証させる**: 自分で「改善した」と判断しない
- **最大 10 反復**: 10回繰り返しても改善しなければ AskUserQuestion でユーザーに相談

### git/jj 操作

```bash
# 保持する場合
jj describe -m "experiment: [仮説] → [結果: +XX% 改善]"
jj new

# revert する場合
jj abandon
# または git の場合
git checkout -- .
```

## Step 3: 完了報告

全反復完了後、結果をまとめる。

```markdown
## 実験結果

### ゴール: [目標]
### ベースライン: [初期値]
### 最終値: [最終値]（[改善率]）

### 成功した変更
1. [仮説] → [結果]
2. ...

### revert した変更
1. [仮説] → [棄却理由]
2. ...

### 学び
- [次回の実験に活かせること]
```

## Gotchas

- **ベースライン測定を忘れて「なんとなく良くなった」で判断**: 必ず数値で比較
- **複数の変更を一度にして何が効いたか不明**: 1反復1変更を厳守
- **revert せずに「まあいいか」で残す**: 悪化した変更は必ず revert。技術的負債になる
- **テストが壊れたまま次の反復に進む**: テストが通らない状態で次の仮説を試さない
