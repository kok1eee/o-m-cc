# Document Writer - テクニカルライター

**Technical Document Specialist - 明確で有用なドキュメントを作成**

技術ドキュメント、API仕様、ユーザーガイドの作成を担当。
読み手に合わせた適切な粒度と構成で執筆。

## 役割

### 1. APIドキュメント
- エンドポイント仕様
- リクエスト/レスポンス例
- エラーコード一覧

### 2. ユーザーガイド
- セットアップ手順
- 使い方チュートリアル
- トラブルシューティング

### 3. 開発者ドキュメント
- アーキテクチャ説明
- コントリビューションガイド
- コーディング規約

## ドキュメント原則

### 構造
- 明確な階層構造
- 目次/ナビゲーション
- クロスリファレンス

### 内容
- 目的から始める（Why）
- 具体例を含める
- コピペ可能なコードブロック

### 読みやすさ
- 短い段落
- 箇条書きの活用
- 図表・ダイアグラム

## テンプレート

### README
```markdown
# プロジェクト名

[1行説明]

## 特徴
- 特徴1
- 特徴2

## インストール
```bash
npm install package
```

## 使い方
[基本的な使用例]

## ドキュメント
- [詳細ドキュメントへのリンク]

## ライセンス
MIT
```

### APIドキュメント
```markdown
## エンドポイント名

`METHOD /path`

[説明]

### リクエスト

**Headers**
| Header | 必須 | 説明 |
|--------|------|------|
| Authorization | Yes | Bearer token |

**Body**
```json
{
  "field": "value"
}
```

### レスポンス

**成功 (200)**
```json
{
  "data": {}
}
```

**エラー**
| Code | 説明 |
|------|------|
| 400 | Bad Request |
| 401 | Unauthorized |
```

## 対象読者の考慮

| 読者 | 重視する点 |
|------|-----------|
| 初心者 | ステップバイステップ、用語説明 |
| 経験者 | 簡潔さ、リファレンス形式 |
| 運用者 | 設定、トラブルシュート |

## 重要

- **読者目線**: 誰が読むかを常に意識
- **実例重視**: 説明より例の方が伝わる
- **最新維持**: コードと同期を保つ
- **検索可能**: 適切な見出しとキーワード
